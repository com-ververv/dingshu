## 1. 目标

在现有 Electron 桌面应用中继续完成 Pexar Lark Agent MVP，重点从“可用的聊天 Agent”推进到“能稳定处理飞书对象、文档 Artifact 和长期会话管理”的产品原型。

本方案覆盖：

- 受控 lark-cli capability registry。
- 基于 Vercel AI SDK + SiliconFlow Kimi-K2.6 的流式 Agent。
- 飞书读写能力审批、错误分类和设置页能力发现。
- Chatbot UI 的会话搜索、草稿、slash commands、工具调用状态。
- 新增右侧文档预览 / Artifact 面板。
- 新增 `@群名`、`@联系人`、`@文档标题` 对象 picker。
- 新增会话重命名。

## 2. 总体架构

```txt
Electron Renderer
  React 19 + Streamdown
  Chat UI / Artifact Panel / Object Picker
  window.api IPC
        ↓
Electron Preload
  contextBridge 安全暴露最小 API
        ↓
Electron Main
  Chat IPC / Lark Object IPC / Settings IPC
  ChatService + Vercel AI SDK streamText
  lark-cli capability registry + approval
        ↓
External Services
  SiliconFlow OpenAI Compatible API
  lark-cli user profile / 飞书 OpenAPI
        ↓
SQLite
  conversations / messages / tool_calls / settings
```

## 3. 已完成基础

### 3.1 Vercel AI SDK 与 SiliconFlow

- 使用 `@ai-sdk/openai-compatible` 接入 SiliconFlow。
- Base URL 固定为 `https://api.siliconflow.cn/v1`。
- 模型使用 `Pro/moonshotai/Kimi-K2.6`。
- API Key 通过本地安全设置或服务端环境变量读取，不暴露到 renderer。
- 聊天流式输出通过 main process 统一调用模型，再用 IPC 推送 delta、done、error、tool event。

### 3.2 lark-cli 受控能力

已实现 `src/main/lark/capabilities.ts` 作为 allowlist registry：

- 每个 capability 显式声明 domain、shortcut、allowed flags、identity、risk、timeout。
- 不开放通用 shell，不开放任意 lark-cli passthrough。
- 写入、删除、外发、覆盖类能力必须走审批。
- `lark_cli_shortcut` 根据 registry 构造 lark-cli 参数，并拒绝未知 capability 与越权 flag。

### 3.3 审批与错误分类

- `lark_doc_create`、`lark_message_send`、写类 `lark_cli_shortcut` 统一走一次性审批。
- 审批事件使用 `tool-call-confirmation-required` 推送到 UI。
- lark-cli 错误分类包括 `auth`、`permission`、`missing_argument`、`missing_scope`、`network`、`not_found`、`timeout`、`unknown`。
- 设置页可展示 lark-cli 路径、授权状态和 capability 数量。

### 3.4 Chatbot UI 基础

已完成：

- 会话侧栏搜索和时间分组。
- 配置状态与当前执行状态。
- 会话级草稿。
- `/new`、`/clear`、`/settings`、`/auth`、`/search`。
- Streamdown Markdown 渲染。
- 工具调用摘要、展开详情、长任务中文状态。

## 4. 本轮实现范围

### 4.1 右侧文档预览 / Artifact 面板

目标：

- 在飞书文档创建审批前，右侧展示标题与 Markdown 正文预览。
- 文档创建成功后，展示飞书链接、标题和复制操作。
- 面板可收起，不阻塞主聊天流程。

实现策略：

- 首版只支持飞书文档类 Artifact。
- 不新增数据库表，直接从已有 tool event 解析：
  - `lark_doc_create` 的 `inputPreview` 提供 `title`、`contentPreview`。
  - `lark_doc_create` 的 `outputPreview` 提供 `title`、`url`、`token`。
- renderer 从当前会话消息中的 tool events 派生 Artifact 列表。
- `pending_confirmation` / `running` 显示为草稿或创建中。
- `completed` 且存在 URL 显示为已创建。
- `failed` / `cancelled` 显示失败或未创建。

边界：

- 不做多版本 diff。
- 不做内嵌文档编辑器。
- 不做表格、图片、文件 Artifact。

### 4.2 飞书对象 Picker

目标：

- 用户在输入框输入 `@` 后，可以搜索并插入飞书群、联系人和文档。
- 选中后在输入框插入稳定引用文本，降低模型猜测对象导致的工具失败。

插入格式：

```txt
@[群:研发群](chat_id=oc_xxx)
@[联系人:张三](open_id=ou_xxx)
@[文档:评估报告](url=https://...)
```

实现策略：

- 新增 main process 只读 IPC：`larkObject:search`。
- 搜索入口只允许三类对象：
  - `contact`：优先调用 `contact +search-user`。
  - `chat`：调用 `im +chat-list` 后在本地按名称过滤。
  - `document`：优先调用 `drive +search`。
- IPC 使用已有 `runLarkCli`，不经过 Agent，也不开放写能力。
- 统一返回 `id`、`type`、`title`、`subtitle`、`reference`、`url`。
- renderer 在 textarea 中检测当前 `@` 查询片段，展示 grouped picker。
- 点击结果后替换当前 `@xxx` 片段为稳定引用文本。

边界：

- 首版不做复杂对象管理面板。
- 首版不做联系人、群和文档的缓存持久化。
- 授权失败、无权限、无结果要在 picker 中给出明确提示。

### 4.3 会话重命名

目标：

- 用户可以整理长期会话历史。
- 重命名只修改本地 `conversations.title`，不影响消息内容。

实现策略：

- 数据库新增 `renameConversation(conversationId, title)`。
- IPC 新增 `chat:renameConversation`。
- preload 和 `window.api` 类型同步暴露。
- UI 支持侧栏会话项重命名：
  - hover 显示重命名按钮。
  - Enter 保存。
  - Esc 取消。
  - 空标题拒绝。
  - 标题最大长度 80 字符。
- 重命名后刷新会话列表并保留当前选中会话。

## 5. 数据与 IPC 设计

### 5.1 Chat IPC

新增：

```ts
chat.renameConversation(conversationId: string, title: string)
```

返回：

```ts
IPCResponse<ChatConversationSummary>
```

### 5.2 Lark Object IPC

新增：

```ts
larkObject.search({
  query: string;
  types?: Array<'chat' | 'contact' | 'document'>;
  limit?: number;
})
```

返回：

```ts
IPCResponse<LarkObjectSearchResult[]>
```

结果结构：

```ts
type LarkObjectSearchResult = {
  id: string;
  type: 'chat' | 'contact' | 'document';
  title: string;
  subtitle?: string;
  reference: string;
  url?: string;
};
```

## 6. 安全策略

- Renderer 不直接执行 lark-cli。
- Object picker 只允许只读查询，不支持写操作。
- `@` 引用只是给模型和工具层提供稳定 ID，不绕过写操作审批。
- API Key 和飞书凭证继续保存在本地安全设置，不进入 Git。
- 工具调用详情和 Artifact 预览只展示已有 tool event 中的裁剪内容。
