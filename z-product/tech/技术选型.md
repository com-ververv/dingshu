# Pexar Lark Agent — 技术选型 v0.3

## 决策摘要

| 维度 | 选型 | 关键理由 |
|------|------|----------|
| 桌面框架 | **Electron** | 跨平台、Node 生态完整、与 lark-cli 同语言栈 |
| 前端 | **React 18 + Vite + TypeScript** | 主流、聊天 UI 现成方案多 |
| Agent 框架 | **Vercel AI SDK v5+** | 原生支持 OpenAI 兼容，无需协议转换 |
| LLM Provider | **硅基流动**（OpenAI 兼容） | 用户指定 |
| 模型 | **Pro/moonshotai/Kimi-K2.6** | 用户指定 |
| 飞书集成 | **@larksuite/cli 内置二进制** | 通过 SDK tool 调用 |
| 存储 | **SQLite + Electron safeStorage** | 本地、加密、轻量 |

## 选型决策记录

### 为什么不用 Claude Agent SDK + 代理？

最初候选方案是 `@anthropic-ai/claude-agent-sdk` + `claude-code-router` 做 Anthropic→OpenAI 协议转换。调研后否决，理由：

1. **绕路**：Kimi-K2.6 本来就是 OpenAI 兼容协议，用 Claude SDK 等于"OpenAI → Anthropic → 再翻译回 OpenAI"
2. **部署债**：claude-code-router 需要常驻 Node 子进程占端口，与 Electron 打包/沙箱兼容性差
3. **稳定性受制于第三方**：CCR 跟随 Claude Code CLI 行为更新

### 为什么不用 hermes-agent？

调研后否决：

1. Python-only，需要捆绑 Python runtime（+80–150MB 包体）
2. 多个原生依赖（ripgrep、ffmpeg、git bash）
3. 嵌入 Electron 复杂度高，跨平台打包工作量大

### 为什么选 Vercel AI SDK？

1. **原生 OpenAI 兼容**：`createOpenAICompatible({ baseURL: 'https://api.siliconflow.cn/v1' })` 直连硅基流动
2. **Agent 能力齐全**：v5 的 `Experimental_Agent` 类已包含 agent loop、tool calling、streaming、`stopWhen` 钩子
3. **打包轻量**：纯 npm 库，无子进程、无端口、无 shell 环境污染
4. **多模型扩展**：未来想加 Claude/GPT/DeepSeek，provider abstraction 天然支持

**取舍**：相比 Claude Agent SDK 缺失内建 subagent / permission 系统（`canUseTool`），MVP 用几十行代码包一层即可。

## 架构图

```
┌─ Electron 渲染进程 (React + Tailwind + shadcn/ui)
│       ↕ IPC（流式消息、工具调用事件、设置读写）
│
├─ Electron 主进程 (Node.js)
│   │
│   ├─ Agent 层
│   │   └─ Vercel AI SDK (Experimental_Agent)
│   │       ├─ tool: shell → 调用内置 lark-cli
│   │       ├─ tool: 文件读写、搜索等内建
│   │       └─ HTTPS → 硅基流动 API
│   │
│   ├─ 工具执行层
│   │   └─ 内置 lark-cli 二进制（subprocess）
│   │
│   ├─ 数据层
│   │   ├─ SQLite（会话历史）
│   │   └─ safeStorage（API Key / appSecret）
│   │
│   └─ 日志：electron-log
│
└─ 内置资源
    ├─ lark-cli 二进制（按平台）
    └─ Node.js 运行时（Electron 自带）
```

## 工具调用方式

Vercel AI SDK 的 tool 定义示例（伪代码）：

```ts
import { tool } from 'ai';
import { z } from 'zod';

const larkShellTool = tool({
  description: '执行 lark-cli 命令操作飞书',
  parameters: z.object({
    command: z.string().describe('完整的 lark-cli 命令'),
  }),
  execute: async ({ command }) => {
    // 主进程内调用 child_process spawn lark-cli
    // 返回 stdout/stderr
  },
});
```

Agent 在 reasoning 时会自动选择是否调用此工具。

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| Kimi-K2.6 在复杂 tool calling 上的可靠性 | MVP M1 阶段做工具链验证；必要时改用 DeepSeek-V3 等 |
| lark-cli 跨平台 stdout 编码（Windows GBK） | 调用时强制 UTF-8 环境变量 |
| safeStorage 在 Linux 上需 libsecret（未来扩展） | MVP 不支持 Linux，规避 |
| 内置 lark-cli 与上游版本同步 | 锁定版本，发版前手动升级测试 |
| Vercel AI SDK 缺 subagent/permission | MVP 不用；后续自研轻量层 |
