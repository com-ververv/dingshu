# Pexar Lark Agent 测试问题记录

日期：2026-05-28

测试方式：`npm run dev` 启动 Electron 应用，使用 Computer Use 插件操作真实窗口。

## BUG-001 P1 写操作没有触发工具级二次确认 UI

功能模块：飞书文档创建、飞书消息发送、工具审批、Artifact 面板

复现步骤：

1. 打开应用并进入已有会话。
2. 输入：`把以下内容创建为飞书文档，标题：Codex 测试审批文档，正文：这是一条自动化测试内容。不要真正执行，先给我确认。`
3. 等待 assistant 完成。
4. 输入：`给研发群发送一条消息：这是一条测试消息。不要真正发送，先给我确认。`
5. 等待 assistant 完成。

实际结果：

- 文档创建场景只返回普通 assistant 文本：“如确认无误，请回复‘确认’，我将立即执行创建。”
- 消息发送场景也只返回普通 assistant 文本：“如确认无误，请回复‘确认’，我将调用发送工具...”
- UI 没有出现 `pending_confirmation` 工具卡片。
- UI 没有出现“仅本次允许 / 拒绝”审批按钮。
- 右侧 Artifact 面板仍为空，没有展示待创建文档草稿。

期望结果：

- 写操作应触发工具级审批事件。
- 聊天流中应展示待确认工具卡片，明确动作、目标、内容和风险。
- 用户必须点击 UI 中的允许按钮后，工具才执行。
- 文档创建应在 Artifact 面板显示待确认标题和正文预览。

证据：

- Computer Use 窗口观察：assistant 仅输出普通确认文本，没有工具卡片和 Artifact 草稿。
- 终端日志对应请求只有 `Chat done ... finishReason=stop`，未出现 `lark_doc_create` 或 `lark_message_send` 工具调用日志。

状态：未修复

## BUG-002 P1 safeStorage 解密失败但 UI 仍显示 API Key 已配置

功能模块：设置面板、凭证状态、聊天发送前置检查

复现步骤：

1. 打开 Settings -> AI。
2. 观察 API Key 状态。
3. 发送普通聊天消息。
4. 查看终端日志。

实际结果：

- Settings -> AI 显示 `API Key 已配置`。
- 发送消息时主进程日志报错：

```text
[SecureSettings] Failed to decrypt setting siliconflow_api_key. The value may need to be saved again.
Error while decrypting the ciphertext provided to safeStorage.decryptString.
```

- 应用仍继续使用环境变量 fallback 完成请求。
- UI 没有提示已保存凭证不可解密，也没有引导用户重新保存。

期望结果：

- 如果已保存的 API Key 无法解密，设置状态不应显示为健康的“已配置”。
- 聊天发送前应给出明确错误或设置提示。
- 如果开发环境允许环境变量 fallback，也应在设置或日志中区分“安全存储可用但保存值损坏”和“环境变量可用”。

证据：

- Settings AI 页显示 safeStorage 可用、API Key 已配置。
- 终端日志记录解密失败。

状态：未修复

## BUG-003 P2 停止生成后顶部状态显示“已完成：stop”

功能模块：聊天流式输出、停止生成、状态文案

复现步骤：

1. 新建会话。
2. 输入普通问题：`请用一句话介绍你自己`
3. 发送后立即点击“停止”。

实际结果：

- 请求仍返回完整 assistant 文本。
- 顶部状态显示 `已完成：stop`。
- assistant 消息状态为“已完成”，不是“已停止”。

期望结果：

- 如果停止成功，应显示“已停止”，消息状态应为 cancelled。
- 如果停止时模型已经自然完成，应显示“已完成”，但不应把 `finishReason=stop` 直接展示成“已完成：stop”。
- 状态文案应区分用户取消和模型 stop finish reason。

证据：

- Computer Use 观察：点击停止后 assistant 完成并显示顶部 `已完成：stop`。
- 终端日志：`[Chat] done ... finishReason=stop`。

状态：未修复

## BUG-005 P2 飞书应用未配置但飞书授权状态显示绿色，状态含义不清晰

功能模块：配置状态、设置面板、飞书授权

复现步骤：

1. 查看左侧配置状态。
2. 打开 Settings -> Lark。

实际结果：

- 左侧状态中：
  - 模型为绿色。
  - 飞书应用为未配置。
  - 飞书授权显示绿色。
- Settings -> Lark 中 App ID / App Secret 均显示未配置。

期望结果：

- 如果 appId/appSecret 未配置，飞书授权状态应解释“已有本地授权 profile，但应用凭证未配置”。
- 左侧配置状态应避免让用户误以为飞书链路完全可用。

证据：

- Computer Use 观察左侧配置状态和 Lark 设置页。

状态：未修复

## BUG-006 P2 会话搜索没有匹配当前会话的最新 assistant 内容

功能模块：会话管理、会话搜索、会话摘要刷新

复现步骤：

1. 在当前会话中发送：`搜索飞书里和测试计划相关的文档，返回前 3 条标题`
2. assistant 返回包含“测试计划”的结果。
3. 在左侧搜索框输入：`测试计划`。

实际结果：

- 左侧显示“没有匹配的会话”。
- 当前会话仍在右侧显示，内容里包含“测试计划”。

期望结果：

- 会话搜索至少应匹配会话标题和最新摘要。
- 如果设计为搜索摘要，当前会话的摘要应在 assistant 完成后刷新。
- 如果不搜索正文，应在 UI 上明确搜索范围。

证据：

- Computer Use 观察：当前聊天内容包含“测试计划”，左侧搜索“测试计划”无匹配。

状态：未修复

## BUG-007 P3 重命名当前会话后如果不匹配当前搜索词，左侧列表立即消失

功能模块：会话重命名、会话搜索、当前会话可见性

复现步骤：

1. 左侧搜索框输入 `请用`。
2. 对当前会话点击重命名。
3. 将标题改为 `功能测试会话` 并回车保存。

实际结果：

- 左侧列表立即变成“没有匹配的会话”。
- 右侧仍停留在当前会话。

期望结果：

- 这是逻辑上可解释的过滤结果，但会让用户误以为当前会话丢失。
- 可以考虑保留当前会话可见、提示因搜索条件被过滤，或保存后清空搜索。

证据：

- Computer Use 观察。

状态：未修复

## BUG-008 P3 恢复上次中断会话时默认显示失败消息

功能模块：会话恢复、中断恢复

复现步骤：

1. 启动应用。
2. 默认恢复最近一次历史会话。

实际结果：

- 最近会话显示 assistant `失败`。
- 文本为：`正在连接模型...` 和 `上次生成已中断，请重新发送。`

期望结果：

- 恢复中断状态本身合理，但 UI 应更明确地标识为“上次中断”，并提供清晰的重新发送操作。
- 当前状态容易让用户以为应用启动失败。

证据：

- Computer Use 首屏观察。

状态：未修复
